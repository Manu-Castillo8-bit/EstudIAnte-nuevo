01 · Visión general

Introducción

¿Qué describe este manual?

El manual de arquitectura describe la organización lógica de EstudIAnte, los componentes de la interfaz, los servicios de aplicación, la persistencia y las integraciones externas.

Su objetivo es facilitar la comprensión del sistema y servir como referencia para futuras modificaciones.

Propósito: ofrecer una visión organizada de los elementos principales del sistema y de cómo se relacionan conceptualmente.
🧭

Comprender

Identificar las capas, responsabilidades y módulos descritos.

🛠️

Dar mantenimiento

Servir como referencia para futuras revisiones y modificaciones.

05 · Operaciones internas

Servicios y lógica de negocio

Responsabilidades que van más allá de la interfaz.

AuthService

Autenticación

Está relacionado con la autenticación y el usuario activo. Su documentación debe aclarar cómo se inicia y finaliza una sesión, cómo se identifica al usuario y cómo se gestionan los errores.

SyncService

Sincronización

Se relaciona con la sincronización de datos locales y remotos, el orden de las operaciones y el tratamiento de cambios.

Aspectos que deben documentarse en SyncService

  • Tipos de datos que sincroniza y orden de las operaciones.
  • Tratamiento de registros nuevos, modificados y eliminados.
  • Errores de red y conflictos entre cambios locales y remotos.
  • Cómo se informa al usuario sobre el estado de sincronización.
Por verificar: el manual señala que debe confirmarse si la versión actual utiliza Supabase Auth o un mecanismo propio. También se debe revisar el almacenamiento de contraseñas.

09 · Supervisión

Módulo de administración

Panel para supervisar contenido, usuarios y actividad.

El manual describe un panel con secciones para usuarios, documentos, cuestionarios, diagramas y resultados. También menciona una vista de detalle de usuario que presenta información de actividad.

Controles necesarios para operaciones administrativas

  • Validación del rol.
  • Autorización en el backend.
  • Comprobación de la propiedad de los registros cuando corresponda.
  • Manejo de errores.
  • Registro de acciones sensibles cuando sea apropiado.
⇄
10 · Intercambio de información

Exportación y sincronización

Archivos que salen del sistema y cambios que viajan entre dispositivo y servidor.

📤

Exportación

El módulo de archivos permite exportar documentos y diagramas, generar archivos HTML para diagramas y copiar código Mermaid.

🔄

Sincronización

Se relaciona con el envío de cambios locales y la descarga de información remota.

Escenarios que la arquitectura debe definir

  • El dispositivo no tiene Internet.
  • El usuario crea un archivo sin conexión.
  • Se restablece la conexión y se ejecuta la sincronización.
  • El servidor rechaza una operación.
  • Existen cambios simultáneos sobre un mismo registro.
Estado de la especificación: el documento indica que la solución de conflictos no debe darse por definida hasta verificar la implementación real.
