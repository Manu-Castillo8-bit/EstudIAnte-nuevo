Una explicación visual y en lenguaje sencillo de las piezas que forman el proyecto: la aplicación, sus pantallas, los datos, la inteligencia artificial y los servicios que trabajan detrás.

La idea en una frase

EstudIAnte es una aplicación de escritorio y móvil para estudiar con documentos: los guarda, permite conversar sobre ellos y crea resúmenes, cuestionarios y diagramas.

1. ¿Qué problema resuelve?

La aplicación busca convertir documentos académicos o de investigación en material de estudio más fácil de usar. En lugar de limitarse a mostrar un archivo, permite guardar documentos, obtener un resumen, hacer preguntas sobre el contenido, generar cuestionarios y representar ideas mediante diagramas.

Para quien estudia

Puede organizar materiales, consultar el contenido como si hablara con un tutor, practicar con preguntas y revisar resultados.

Para quien administra

Existe un panel para consultar usuarios, documentos, cuestionarios, diagramas, resultados y ciertos límites de uso de IA.

La descripción funcional se basa en el README del proyecto y en las pantallas y servicios del código. La aplicación principal es nativa/multiplataforma; esta guía, en cambio, sí es una página HTML que se abre en un navegador.

2. El mapa general: piezas como un equipo

Imagina un restaurante: la pantalla es el mostrador, los servicios son el personal que prepara las solicitudes, la base de datos es la despensa y el servidor de IA es un proveedor externo especializado.

Persona→Pantalla de la app→Servicio de la app→SQLite o Supabase
Servicio de IA→Función segura de Supabase→Proveedor de IA→Respuesta a la app
Qué significa: las pantallas no deberían tener que saber cómo se conecta la nube o cómo se lee un PDF. Piden ese trabajo a un módulo especializado, que devuelve el resultado para mostrarlo.

Tres grandes capas

1 · Presentación

Archivos .xaml definen el aspecto y los controles; archivos .xaml.cs conectan botones y eventos con las acciones.

2 · Lógica

Los servicios hacen tareas como iniciar sesión, analizar documentos, generar cuestionarios y sincronizar.

3 · Persistencia e integración

Los modelos describen los datos; SQLite los guarda en el dispositivo y Supabase puede almacenar y compartir datos por internet.

3. ¿Qué pasa cuando alguien la usa?

Al abrir la aplicación

App.xaml.cs decide la primera ventana. Intenta restaurar una sesión recordada con AuthService. Si hay usuario, abre la aplicación principal y lanza una sincronización en segundo plano; si no, muestra la pantalla de introducción.

Al trabajar con un documento

  1. La persona selecciona o administra sus archivos desde las pantallas de documentos.
  2. Los servicios de documentos extraen o preparan el contenido; el proyecto incluye una herramienta específica para analizar PDF.
  3. Se guarda información como nombre, tipo, tamaño, resumen y estado.
  4. La IA puede ayudar a resumir, responder preguntas o crear ejercicios a partir del contenido disponible.
  5. La información se conserva localmente y puede sincronizarse con Supabase cuando hay conexión.

Al completar un cuestionario

El generador produce las preguntas; el modelo de cuestionario y el modelo de pregunta guardan su estructura. Los resultados pueden registrar la puntuación, el total y el tiempo empleado.

Al quedarse sin conexión

SQLite permite conservar datos en el equipo. SyncService mantiene cambios pendientes —incluidos borrados— y trata de enviarlos o actualizar los datos al sincronizar con la nube. Las funciones que dependen de internet, como solicitar una respuesta nueva a un proveedor remoto de IA, sí requieren conexión.

6. Qué información guarda y dónde

Un modelo es la ficha que define qué datos tiene una cosa. Por ejemplo, un documento tiene identificador, nombre y estado; una pregunta pertenece a un cuestionario.

SQLite: el cuaderno del dispositivo

Base de datos local, útil para conservar información en el equipo y trabajar con algunos datos sin conexión.

Supabase: el archivador en la nube

Servicio alojado que ofrece PostgreSQL (base de datos) y otros componentes. La aplicación lo usa para guardar, consultar y sincronizar información entre instalaciones.

Modelos identificados

ModeloQué describe
UsuarioUna cuenta y sus datos asociados, como identificador, nombre y rol.
DocumentoUn archivo de estudio y sus metadatos, como tipo, tamaño, estado y resumen.
TemaUn tema o agrupación para organizar el material.
Chat y MensajeUna conversación y cada intervención que contiene.
Cuestionario y PreguntaUn ejercicio de evaluación y sus preguntas.

UsoIA y ConfiguracionIAContadores de uso y configuración de límites de IA.
SyncBorradoUna nota local de qué registro hay que borrar en la nube durante la próxima sincronización.
SyncModelBase común para modelos compartidos entre SQLite y Supabase, evitando que campos técnicos de la nube se guarden como columnas locales.

El archivo supabase\schema.sql documenta las tablas remotas. El esquema incluye entidades de usuarios, documentos, temas, chats y mensajes, cuestionarios y preguntas, resultados, diagramas y uso/configuración de IA. Algunas entidades se relacionan entre sí por identificadores: por ejemplo, los mensajes con su chat y las preguntas con su cuestionario.

Cómo se sincroniza

El flujo general es “subir los cambios locales” y “bajar la versión de la nube”. La sincronización también registra eliminaciones para que un elemento borrado sin conexión no reaparezca al actualizar. El código intenta evitar duplicar filas y trata de comparar ciertos cambios antes de actualizarlos.

7. Cómo se conecta con inteligencia artificial

La aplicación separa la conversación de la infraestructura del proveedor. En vez de poner las claves privadas de Gemini o Groq dentro de la aplicación, el diseño descrito por el proyecto envía la solicitud a una Edge Function de Supabase. Esa función del servidor se comunica con el proveedor de IA.

Pregunta o instrucción→App→functions/v1/gemini→Proveedor elegido

La función se encuentra en supabase\functions\gemini\index.ts. Recibe datos como el texto de la instrucción, el proveedor solicitado y la opción de búsqueda web, y devuelve el resultado o un error. El gestor puede informar cuando hay saturación o se agotó la cuota; según el README, la app pregunta a la persona si desea intentar con el siguiente proveedor, en vez de cambiar silenciosamente.

Proveedores descritos por el proyecto

  1. Google Gemini, primera opción descrita.
  2. Groq, alternativa de servidor.
  3. OpenRouter, otra alternativa que el README describe con modelos gratuitos.
  4. Gemini local, opción documentada para usar una clave propia configurada localmente.
  5. Exa aparece en el código como proveedor relacionado con búsqueda web.

La disponibilidad real de cada proveedor depende de la configuración de Supabase, sus secretos, cuotas y del código desplegado. El README describe el orden de respaldo, mientras que los proveedores concretos pueden cambiar con las versiones.

Sobre las claves: las claves privadas de proveedores deben mantenerse en el servidor como secretos y no publicarse en esta guía ni en el repositorio. La clave pública de Supabase que una aplicación cliente utiliza no equivale por sí sola a una clave privada de proveedor; las reglas de acceso de la base de datos siguen siendo importantes.

Otros usos de IA

El README describe generación de resúmenes, preguntas de repaso, respuestas a dudas, cuestionarios de 5, 10, 15 o 20 preguntas y diagramas Mermaid de flujo o mapas mentales. El usuario puede estudiar a partir de documentos o de conversaciones, según la función.

9. Plataformas, arranque y recursos visuales

El proyecto apunta a Android, iOS, Mac Catalyst y Windows, sujeto a las condiciones de compilación y a los requisitos de cada sistema. Las carpetas dentro de Platforms\ contienen el arranque y metadatos específicos que cada sistema operativo exige.

  • Android: manifiesto, actividad principal y clase de aplicación.
  • iOS y Mac Catalyst: delegados, archivos de configuración y punto de entrada.
  • Windows: manifiesto, recursos y arranque de la ventana.

MauiProgram.cs configura la aplicación MAUI; App.xaml y Resources\Styles\ definen estilos y temas compartidos. Resources\AppIcon\, Resources\Splash\, Resources\Images\ y Resources\Fonts\ contienen icono, pantalla de inicio, imágenes y tipografías.

El repositorio también incluye manuales en HTML, PDF y texto bajo EstudIAnte\Manuales\, además de un diagrama entidad-relación editable en Diagramas\.

11. Consideraciones importantes al interpretar el proyecto

  • No es solo un sitio web: la aplicación de estudio está escrita con MAUI y se instala como app; el HTML de esta guía es documentación separada.
  • La nube requiere configuración: Supabase debe tener las tablas esperadas por schema.sql y la función de IA desplegada. Las claves de los proveedores se configuran como secretos del servidor.
  • Sincronizar no es lo mismo que respaldar: la sincronización intenta igualar datos entre dispositivo y nube, pero la política de conflictos y el estado de conexión afectan el resultado.
  • Hay dependencias de conexión: las consultas a IA remota y la sincronización necesitan acceso a internet.
  • Revisar el manejo de credenciales: el código del panel administrativo contiene una indicación de que, al mostrar datos de usuarios desde Supabase, las contraseñas se presentan en texto legible por requisito del proyecto. Esto es una decisión sensible: no debe interpretarse como una práctica segura; conviene revisar cómo se almacenan, quién puede verlas y migrar a autenticación y almacenamiento con contraseñas protegidas antes de un uso con cuentas reales.
  • La configuración local puede variar: el resultado depende de las versiones instaladas, secretos del entorno y configuración del proyecto Supabase desplegado.
Esta guía describe la organización observada y los objetivos declarados en los archivos del repositorio; no certifica que un servicio externo esté configurado o disponible en este momento.

12. Glosario para empezar

Aplicación multiplataforma

Un mismo proyecto que puede prepararse para ejecutarse en más de un sistema operativo, adaptando ciertas partes a cada plataforma.

API

Una puerta de comunicación acordada: la aplicación envía una solicitud con un formato esperado y recibe una respuesta.

Base de datos

Un sistema organizado para guardar y buscar información en lugar de depender de una colección desordenada de archivos.

Edge Function

Un pequeño programa que se ejecuta en la infraestructura del servicio en la nube. En este proyecto, hace de intermediario entre la app y ciertos proveedores de IA.

Modelo

Una definición de qué datos tiene una entidad, como un usuario, un documento o un cuestionario.

Paquete o biblioteca

Código reutilizable creado por otros equipos. El proyecto lo incorpora para no tener que construir desde cero funciones como leer PDF o hablar con una base de datos.

Sincronización

El proceso de intercambiar cambios entre el dispositivo y la nube para que ambos tengan información coherente.

SQLite / PostgreSQL

Dos tecnologías de base de datos: SQLite suele guardarse dentro del dispositivo; PostgreSQL se usa aquí como base de datos de Supabase en la nube.

XAML / C#

XAML describe el aspecto de la pantalla; C# implementa las acciones y la lógica que ocurre al interactuar con ella.
